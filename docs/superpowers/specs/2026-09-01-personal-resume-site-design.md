# 马毓廷个人简历主站设计规格

日期：2026-09-01

## 1. 目标

将现有“四个 AI Agent 项目案例集”扩展为面向招聘方的个人简历主站。网站的第一主线是“马毓廷——AI 产品经理”，实习、教育、能力与联系方式构成主要阅读路径；四个 Agent 项目作为能力证据，在首页以精选卡片出现，并分别进入独立项目详情页。

网站不照搬 PDF 简历，不提供原始 PDF 下载。它只保留能帮助招聘方快速形成判断的重点内容，并通过网页的空间、动效和跨页面结构补充纸质简历无法表达的人机协作过程与项目证据。

## 2. 已确认的内容边界

- 职业定位：AI 产品经理。
- 视觉主题：编辑式个人叙事与具身智能氛围结合。
- 头像：使用 `/Users/mayuting/Downloads/116334.JPG`，在“关于我”区域展示，不与首屏视频争夺焦点。
- 首屏视频：使用用户提供的 `https://d8j0ntlcm91z4.cloudfront.net/user_38xzZboKViGWJOttwIXH07lWA1P/hf_20260601_110537_3a579fa0-7bbc-4d94-9d25-0e816c7840f5.mp4`；桌面端支持鼠标横向移动控制视频帧，移动端静音自动播放。
- 个人信息：按用户明确选择，可公开电话、邮箱、现居城市、年龄、性别、身高、体重和民族。
- 实习经历：重点展开千寻智能、京东科技和网易云音乐；科大讯飞保留为简历式摘要。
- 量化结果：不设置独立“数字证明”区域，只放入其对应的实习经历。
- 项目：用工合规智能系统、MockInterview、Career Pathfinder、FillResume 智能网申助手，首页展示摘要，独立页面展示完整案例。
- PDF：不复制到站点，不提供公开下载入口。
- 文案：保留英文栏目标签；中文辅助文案必须说明产品对象、职责范围或结果，不写泛化口号。

## 3. 设计方向

### 3.1 核心概念

“让 AI 从能力走向真实交互”。

具身智能感不通过机器人图标、霓虹控制台或大量科技词堆叠实现，而通过以下机制表达：

- 视频环境随鼠标横向动作改变，体现感知与行动关系。
- 细线、坐标、状态节点和滚动进度表达空间与任务推进。
- 生活照片、温暖中性色和编辑式排版保留人的存在。
- 交互动效克制、可预测，不遮挡招聘信息，不制造阅读负担。

### 3.2 视觉语言

- 主色：近白、墨绿、深灰黑；视频和照片中的暖红作为自然点缀。
- 项目强调色：合规绿、面试橙、职业紫、网申蓝；仅用于项目状态、链接和关键结果。
- 标题字体：具有编辑感的中文衬线或系统可用等价字体。
- 正文字体：清晰、克制的中文无衬线字体；不机械照搬参考 Prompt 中的 Inter。
- 网格：桌面 12 栏，移动端 4 栏；主页和项目页共享容器宽度、边距、分隔线与圆角尺度。
- 卡片：采用轻边框、低阴影和充足留白；避免旧案例集中过厚、过密的卡片堆叠。

## 4. 信息架构

### 4.1 全站导航

统一导航品牌为“马毓廷 ✣”，主页提供“经历 / 项目 / 教育 / 关于 / 联系”锚点。项目页使用同一导航高度、字体和品牌标记，并提供“返回主页”和“下一项目”。移动端折叠为全屏菜单。

### 4.2 主页

1. **Hero**
   - 英文标签：`AI PRODUCT MANAGER · EMBODIED INTELLIGENCE`
   - 主标题：`让 AI 从能力走向真实交互`
   - 中文说明：聚焦多模态交互、语音 Agent 与 AIoT 产品，说明从需求定义、策略设计、跨团队推进到上线验证的完整实践。
   - 背景视频承担环境氛围；正文保持高对比和稳定布局。
   - 能力标签：多模态交互、Agent / RAG、语音产品、AI × IoT。

2. **关于我**
   - 英文标签：`00 / HUMAN IN THE LOOP`
   - 使用个人照片。
   - 说明实践如何从智能座舱数据、IoT 商业化延伸到语音交互和具身机器人产品。
   - 展示武汉大学硕士、现居武汉、国家二级运动员等高辨识度信息。

3. **实习经历**
   - 英文标签：`01 / FIELD EXPERIENCE`
   - 三段重点实习采用统一结构：时间与领域、公司与岗位、职责摘要、关键行动、对应量化结果。
   - 千寻智能：问答响应约 5 秒降至约 2 秒、前台迎宾 MVP、WRC 现场交付。
   - 京东科技：炒菜机器人 0-1、100+ 日志分析、90% 体验问题一周内解决、口头禅重复率 40% 降至 10%、菜谱满意度提升至 90% 以上。
   - 网易云音乐：小米生态会员合作、TV 频道集成、MAU 540 万增至 900 万、覆盖 6000 万电视设备。
   - 科大讯飞：压缩为早期数据产品经历，保留标注规范、三类平台原型与交付效率提升约 100%。

4. **Agent 项目**
   - 英文标签：`02 / SELECTED AGENT WORK`
   - 四张统一比例卡片，每张只展示项目定位、核心结果和进入详情页的链接。
   - 项目卡使用各自强调色，但共享结构、排版、动效和悬停反馈。

5. **教育、能力与荣誉**
   - 武汉大学信息资源管理硕士、电子商务本科。
   - GPA 3.7 / 4.0、CET-6 535、优秀学生干部、“互联网+”校级三等奖。
   - 能力按产品工作分组：AI 产品方法、Agent 与模型、数据与工程、多模态与 IoT，避免关键词墙。

6. **联系与个人信息**
   - 展示用户明确允许公开的完整个人信息。
   - 电话和邮箱提供可点击链接。
   - 不出现 PDF 下载按钮。

### 4.3 项目详情页

四个项目使用同一模板：

1. 统一导航与返回主页入口。
2. 项目 Hero：英文项目编号、项目名称、定位、对象、核心结果和项目强调色。
3. 项目概览：为什么做、解决谁的问题、当前完成度。
4. STAR：Situation、Task、Action、Result。
5. 人机协作：我负责、AI Agent 负责、协作闭环。
6. 核心挑战与解决方案：不重复 STAR，突出关键判断和方案转折。
7. 工具与模型：选择、用途与原因。
8. 结果、证据与诚实边界。
9. 上一项目 / 下一项目导航。

项目页继承主页的英文标签、字体、网格、分隔线、圆角、动效和页脚。不得保留一套独立的“旧案例集”视觉；差异仅来自项目强调色和具体内容。

## 5. 文案规范

- 保留英文标签，例如 `HUMAN IN THE LOOP`、`FIELD EXPERIENCE`、`SELECTED AGENT WORK`。
- 中文正文优先使用具体名词和动作：产品对象、负责模块、推动动作、量化结果。
- 禁止仅表达态度而无信息量的句子，例如“通过真实日志和用户反馈把能力变成体验”。
- 主页负责快速判断，项目页负责证据深度；同一事实不在多个区块重复展开。
- 不夸大未验证结果。项目中的测试、效果和边界继续以 `lib/projects.ts` 的证据为准。

## 6. 交互与动效

### 6.1 首屏视频

- 桌面端：监听鼠标横向移动，根据位移增量更新目标播放时间；限制在视频时长范围内。
- 移动端：关闭鼠标 scrub，视频静音、内联自动播放。
- 减少动态偏好：停止 scrub 和自动播放，显示稳定首帧或后备背景。
- 视频加载失败：显示与全站配色一致的静态渐变和感知网格，不影响任何文本或导航。

### 6.2 页面动效

- 首屏标题采用一次性打字机或分段入场，不能反复循环。
- 区块进入视口时使用统一的淡入与轻微位移动效。
- 卡片悬停使用边框、箭头和轻微位移反馈，不使用大幅缩放。
- 全站只保留首屏、滚动进入、悬停三类动效，统一时长和缓动。
- 所有动效遵守 `prefers-reduced-motion`。

## 7. 技术架构

### 7.1 静态多页构建

目标托管为 GitHub Pages，继续使用 Vite 静态构建，输出到 `dist-pages`。

- `index.html`：个人主页入口。
- `projects/compliance/index.html`
- `projects/mock-interview/index.html`
- `projects/career-pathfinder/index.html`
- `projects/resume-autofill/index.html`

Vite 使用多入口构建，保证每个项目拥有可直接访问、可刷新、可分享的静态 URL，避免 GitHub Pages 对客户端路由回退的限制。

### 7.2 数据与组件

- 新增结构化简历数据文件，集中维护个人信息、教育、经历、技能和荣誉。
- 继续使用 `lib/projects.ts` 作为四个项目的单一事实来源，按需要补充“核心挑战”字段。
- 共享组件：站点导航、英文标签、区块标题、经历条目、项目卡、项目详情模板、页脚、动效控制器。
- 项目详情入口根据页面声明的项目 ID 读取对应数据；ID 不存在时显示明确错误与返回主页入口。
- 使用 `motion/react` 统一菜单、区块入场与卡片过渡；视频 scrub 使用独立 React hook，并统一遵守减少动态偏好。

## 8. 响应式与无障碍

- 桌面端首屏为文字与视频叠加构图；移动端将文字置前、视频置后，保证信息优先。
- 移动端不依赖 hover 或鼠标 scrub。
- 导航、项目卡、电话和邮箱可通过键盘访问。
- 图片提供替代文本；装饰性网格和轨迹对辅助技术隐藏。
- 颜色对比满足正文可读性，项目强调色不能成为唯一的信息载体。
- 视频静音，无强制声音；页面不自动滚动。

## 9. 验证与测试

1. 内容契约：主页包含三段重点实习、一段摘要经历、教育、能力、荣誉和四个项目入口；不包含 PDF 下载入口。
2. 文案契约：英文标签保留；泛化口号不进入关键辅助文案。
3. 路由契约：四个项目静态 URL 均构建成功，主页链接与上下项目导航有效。
4. 视觉契约：主页和项目页引用同一设计 token 与共享组件。
5. 交互测试：桌面视频 scrub、移动端播放、视频失败降级、减少动态偏好。
6. 响应式检查：桌面、平板、手机首屏、导航、经历和项目卡无溢出。
7. 构建验证：内容测试、UI 契约测试、TypeScript、Vite Pages 构建全部通过。
8. 发布验证：GitHub Pages 主页、四个项目页、JavaScript、CSS、视频后备与头像资源均返回成功状态。

## 10. 非目标

- 不把 PDF 简历逐字复制为网页。
- 不提供 PDF 下载。
- 不新增后台、登录、数据库或内容管理系统。
- 不自动播放声音。
- 不为“科技感”引入与内容无关的 3D 模型、粒子系统或机器人素材。
- 不修改四个项目已经确认的事实边界。
